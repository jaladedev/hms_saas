feat(audit): setup history screen and audit_actor_names (029)

Why: setup changes (room types, rooms, rates, tax rules, staff roles) have been
audited since 024/028 but nobody could read the trail, and tax rules are now
editable from the app. This adds /app/settings/history so an owner or general
manager can see who changed what, with old and new values.

- reads audit_logs as the signed-in user: the audit_logs_select policy
  (audit.view at the row's property) decides what shows; the page adds no
  permission logic of its own
- migration 029 audit_actor_names(user_ids): display names for the people on
  a page, only for people in a hotel group where the caller holds audit.view.
  Needed because a general manager has audit.view but not staff.manage, so
  staff_directory() cannot name anyone for them. Tests in 27_audit_actor_names.sql
- actions are listed by name, not prefix: room.blocked and room.transferred
  also start with "room." and are not setup
- things changed are named from the live tables by id (an update row stores
  only the changed columns), falling back to the name stored with the row

Known gap: staff.status_changed rows are written without a property, which the
select policy hides, so suspensions and removals do not show yet.

Checked: typecheck, npm test (370 passed), next build, npm run db:test (ALL
TESTS PASSED, PostgreSQL 16). Not checked in a browser or over HTTP.
